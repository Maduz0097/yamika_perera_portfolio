## Technical stack and Cloudflare deployment

Use **Next.js App Router + TypeScript + Tailwind CSS** with **static
export** deployed to **Cloudflare Pages**. This portfolio is
content-focused and does not need server-side runtime features; static
output is fast, simple, and low maintenance.

Official current docs: - Next.js static export on Pages:
https://developers.cloudflare.com/pages/framework-guides/nextjs/deploy-a-static-nextjs-site/ -
Cloudflare Pages Git integration:
https://developers.cloudflare.com/pages/get-started/git-integration/ -
Cloudflare Next.js Workers guidance:
https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/

Configuration: - Set `output: "export"` in `next.config.ts` /
`next.config.js`. - Build command: `npx next build`. - Build output
directory: `out`. - Use static-compatible images; do not rely on a
server image optimisation endpoint. - Avoid API routes, Server Actions,
server-only runtime dependencies, and features incompatible with static
export. - Store content in typed local data modules. - Connect
Cloudflare Pages to GitHub. Production branch `main`; pushes deploy
production and preview branches/PRs should use preview deployments.

Cloudflare's current guidance recommends vinext for new Next.js apps
that need dynamic execution on Workers. That is not required for this
static portfolio. Do not add vinext or SSR unless a real requirement
appears. If static export becomes insufficient, explain trade-offs and
propose the current Cloudflare Workers path rather than silently
changing architecture.
